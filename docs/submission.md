# Submission checklist

Local implementation and submission readiness are separate. Check items only with observed evidence.

- [ ] Provider probe passes with the configured live accounts.
- [ ] Dedicated Walrus Mainnet namespace contains at least ten distinct completed memories with blob receipts.
- [ ] A fresh verification process recalls those records and cites them in changed recommendations.
- [ ] A purpose-scoped correction persists and leaves the other purchase type unchanged.
- [ ] Live supplier discovery returns inspectable sources without fabricated quotes or reliability.
- [ ] Tatum matches an authorized existing simple transfer and rejects an incorrect expected amount.
- [ ] Lint, typecheck, unit/integration tests, desktop/mobile browser tests, and production build pass on the final revision.
- [ ] Deployed app survives restart with durable outbox and session/budget storage.
- [ ] Public sample cannot read operator data or trigger paid providers.
- [ ] Public repository URL is published after checking staged files for secrets and generated data.
- [ ] Blog and demo recording are published using actual verified evidence.
- [ ] Hackathon form is submitted with the final URLs and confirmation recorded.

| Deliverable | URL / evidence |
|---|---|
| Public demo | Pending |
| Public repository | Pending |
| Blog | Draft: `docs/blog-draft.md` |
| Recording | Sequence: `docs/demo.md` |
| Live verification | `artifacts/verification/submission-readiness.json` after a real run |

The verifier intentionally keeps publication blocked until the release checklist is completed separately. A nonzero exit caused by missing live configuration must not be relabeled a successful submission.
